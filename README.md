# Тест на Синдром Титаника — общий источник для двух версий

Раньше индивидуальный и групповой тесты были двумя независимыми копиями кода в
Tilda. Правка в одной не доезжала до другой, и версии разошлись: в групповой
застряли пять мобильных фиксов, в индивидуальной — phone gate.

Теперь код один. Различия версий сведены к трём вещам:

| Что различается | Где живёт |
|---|---|
| Отступы под шапку, вид баннера, скрытие плавающей CTA | `src/group/group.css` |
| Панель хоста и групповой отчёт | `src/group/host.html`, `src/group/session.js` |
| Phone gate, метка версии в выгрузке | `src/individual/individual.css` + `TS_CONFIG` в сниппете |

Всё остальное — общее ядро в `src/core/`.

## Как править

1. Меняешь файл в `src/core/` (или в слое версии, если правка только для неё).
2. `python3 build.py` — собирает `dist/`.
3. `python3 tools/preview.py` — открываешь локально и проверяешь до выкладки:
   - [индивидуальная](dist/preview-individual.html)
   - [групповая](dist/preview-group.html) (хост: `?host=1&hostKey=<ключ>`, участник: `?session=<код>`)
4. Перетаскиваешь папку `dist/` на хостинг — правка доезжает до обеих страниц.

В Tilda при этом заходить не нужно: блоки T123 содержат только ссылки на ядро.

## Как ядро узнаёт, какая это версия

Групповая страница ничего не меняет в ядре — она к нему прицепляется:

- ядро при показе результата шлёт `window.dispatchEvent(new CustomEvent("titanic:result"))`,
  групповой контроллер на это подписан;
- контроллер сам вешает `.is-group-session` на `#titanicQuiz`, а весь групповой
  CSS написан под этот класс.

Поэтому в `core/` нет ни одного `if (групповая)`. Единственный переключатель —
`window.TS_CONFIG` в сниппете: `phoneGate` и `testVersion`.

## Первая установка в Tilda (один раз)

```
python3 build.py --snippet individual   # сниппет в буфере обмена
python3 build.py --snippet group
```

Вставить содержимое буфера в блок T123 соответствующей страницы **вместо всех
нынешних блоков квиза**. У групповой страницы сейчас четыре блока T123
(`rec2952667501` CSS, `rec2952845501` HTML, `rec2952849401` JS, `rec2952849201`
контроллер) — все четыре заменяются одним.

Перед заменой стоит выгрузить текущие блоки на случай отката: export-zip
проекта в Tilda даёт их целиком.

## Тесты

Прогоняются в headless-браузере против локального сервера над `dist/`:

```
cd dist && python3 -m http.server 8765 &
B=~/.claude/skills/gstack/browse/dist/browse
$B goto http://localhost:8765/preview-individual.html && $B eval tools/qa.js
$B js "window.__QA.results.filter(function(r){return !r.pass}).map(function(r){return r.t}).join()"
```

Групповую версию без `?session=<код>` открывать нельзя: без него страница по
дизайну уходит в хост-режим (`accessDeniedMode`) и прячет весь `#titanicQuiz`
через `display: none` — синтетические клики в тесте всё равно «проходят»
вопросы (`.click()` работает и на скрытых элементах), а последняя проверка на
реальную видимость гейта закономерно падает. Код сессии может быть любым —
запрос к `GROUP_SESSION_ENDPOINT` глушится тем же стабом сети:

```
$B goto "http://localhost:8765/preview-group.html?session=QATEST01" && $B eval tools/qa.js
```

- `tools/qa.js` — сквозной прогон: 39 проверок для индивидуальной, 36 для
  групповой (прохождение, валидация гейта, Enter, экран результата, состав
  payload, phone gate, вёрстка).
- `tools/qa-matrix.js` — матрица скоринга: 13 наборов ответов, все границы
  уровней риска, прогон в iframe.
- `tools/qa-score.js` — один набор ответов, задаётся в хэше `#qa=333333333333333`.

Сетевые вызовы во всех тестах заглушены — **ни один прогон не пишет в боевой
Google Sheet**. Заглушка перехватывает и `fetch`, и `sendBeacon`, поэтому по
её логу видно, что именно ушло бы в таблицу.

## Проверка, что версии не разъехались

```
python3 check.py
```

Скачивает обе живые страницы и сверяет с `src/`. Пока страницы не переведены на
подключаемое ядро, показывает, чем именно они отличаются. После перевода
печатает «подключает ядро с хостинга» — сверять больше нечего, дрейф
невозможен по построению.

## Хостинг

`build.py` подставляет в сниппеты `BASE_URL` — поменяй его в одном месте, если
адрес другой. `dist/_headers` просит хостинг всегда перепроверять файлы, чтобы
правка доезжала сразу, а не через кеш.

Важно: и разметка, и логика приезжают с хостинга. Если он недоступен, квиз не
покажется вообще. Это плата за то, что правка делается один раз.

## Выкладка и откат

Проект живёт в приватном репозитории `rnvnt/titanic-quiz`. Коммит в `main` →
Netlify собирает по `netlify.toml` (`python3 build.py` + `node --check` по
`dist/core.js` и `dist/session.js`) и выкладывает. Терминал нужен только для
локальной проверки: тексты правятся в веб-редакторе GitHub (для команды —
`Инструкция.md`).

Откат — кнопка Revert на нужном коммите. Сломанный синтаксис роняет сборку,
на сайте остаётся прошлая рабочая версия.

Запасной путь в обход репозитория:

```
python3 build.py && npx netlify-cli deploy --dir=dist --prod --no-build
```
